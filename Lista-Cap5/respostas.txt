LISTA DE EXERCÍCIOS – CAPÍTULO 5 – PIF
Respostas das questões teóricas – 01 a 06

Questão 01
a) O protótipo é float celsius(float);, declarado antes da main(). Ele informa ao compilador que existe uma função chamada celsius, que recebe um float e retorna um float. A chamada é c = celsius(f);, dentro da main(), quando a função é utilizada. A definição aparece depois da main(), em float celsius(float fahr) { ... }, e contém as instruções executadas pela função.
b) O protótipo permite que o compilador conheça antecipadamente o nome, o tipo de retorno e os parâmetros da função. Assim, ele consegue verificar se a chamada está de acordo com a declaração. Sem o protótipo e com a definição depois da main(), o compilador não teria essa informação antecipada e poderia emitir um diagnóstico por chamada sem declaração adequada; a verificação dos argumentos ficaria comprometida.
c) O tipo da função é float, porque esse é o tipo do valor devolvido por return. Os parâmetros indicam os dados que a função recebe, mas não determinam o tipo do resultado. Uma função pode, por exemplo, receber dois int e retornar um float.

Questão 02
a) Uma função C devolve um único valor diretamente por meio de return. Na expressão return soma, media;, a vírgula é o operador vírgula: a expressão soma é avaliada e descartada, e o valor de media é o que efetivamente é retornado. Portanto, o código não devolve os dois resultados.
b) O return; encerra imediatamente a execução de uma função void, sem devolver um valor. Ele não é obrigatório no final de uma função void: quando a execução chega ao fim do corpo, a função termina naturalmente. Ele é útil quando queremos encerrar a função antes, como no caso de erro.
c) Uma implementação possível é:
    float calcularMedia(int a, int b, int c) {
        int soma = a + b + c;
        return soma / 3.0f;
    }

    int calcularSoma(int a, int b, int c) {
        return a + b + c;
    }
São duas funções porque cada chamada retorna um único valor. Separar as responsabilidades deixa claro qual resultado cada função fornece.

Questão 03
a)
- void exibe_mensagem(char* msg): recebe um parâmetro (char*) e não retorna valor.
- int obter_codigo(void): não recebe parâmetros e retorna um int.
- void limpar_tela(void): não recebe parâmetros e não retorna valor.
b) Uma função com retorno calcula ou consulta algo e entrega um valor para quem a chamou. Exemplo: int soma(int a, int b). Um procedimento (void) executa uma ação sem entregar um resultado por return. Exemplo: void exibeMenu(void), que apenas mostra opções na tela.
c) Não. limpar_tela() tem retorno void, então não fornece um valor que possa ser atribuído a x. A chamada correta é apenas limpar_tela();.

Questão 04
a) O caso base é n == 0, que retorna 1. O passo recursivo é n * fatorial(n - 1), que chama a própria função com um valor menor. Sem o caso base, as chamadas continuariam sem uma condição de parada, podendo consumir toda a pilha de execução e causar falha.
b) Rastreamento de fatorial(4):

Empilhamento:
    fatorial(4) = 4 * fatorial(3)
    fatorial(3) = 3 * fatorial(2)
    fatorial(2) = 2 * fatorial(1)
    fatorial(1) = 1 * fatorial(0)
    fatorial(0) = 1  (caso base)

Desempilhamento:
    fatorial(0) retorna 1
    fatorial(1) retorna 1 * 1 = 1
    fatorial(2) retorna 2 * 1 = 2
    fatorial(3) retorna 3 * 2 = 6
    fatorial(4) retorna 4 * 6 = 24
c) Cada chamada recursiva cria um novo registro na pilha de execução, armazenando parâmetros, variáveis locais e o ponto para onde a execução deve voltar. Quando o caso base é alcançado, as chamadas começam a terminar em ordem inversa. Sem caso base, a pilha pode crescer até exceder o limite disponível.

Questão 05
a) SQR(2+3) expande para ((2+3)*(2+3)), resultando em 25. DOBRO(2+3) expande para 2+3*2, resultando em 8, pois a multiplicação tem precedência sobre a soma. A macro SQR protege o argumento e a expressão inteira com parênteses; DOBRO não.
b) #define é uma diretiva de pré-processamento, não uma instrução C comum; por isso não termina com ponto e vírgula. Usar nomes em maiúsculas é uma convenção que ajuda a diferenciar macros e constantes simbólicas de variáveis e funções.
c) #define PRN (n) printf("%d", n) define uma macro sem parâmetros chamada PRN, pois há um espaço entre o nome e (n). A forma correta é #define PRN(n) printf("%d", (n)). Uma macro é expandida pelo pré-processador antes da compilação e pode avaliar um argumento mais de uma vez; uma função comum tem parâmetros tipados e executa em tempo de execução.

Questão 06
a) #include <stdio.h> usa a forma com sinais de menor e maior, normalmente utilizada para cabeçalhos das bibliotecas padrão ou caminhos de inclusão configurados pelo compilador. #include "areas.h" usa aspas, normalmente para um cabeçalho do próprio projeto; o compilador procura primeiro próximo ao arquivo que contém a diretiva.
b) #undef SOMA remove a definição anterior da macro SOMA. Depois disso, ela não pode mais ser expandida como macro, a menos que seja definida novamente. #undef recebe apenas o nome da macro, sem parâmetros: #undef SOMA.
c) Se DEBUG não estiver definido, será selecionado o bloco do #else, imprimindo Modo normal. Essa escolha ocorre durante o pré-processamento, antes da compilação e da execução. As diretivas controlam quais trechos entram no código processado; elas próprias não são instruções executadas e não aparecem como diretivas no executável final.
